# Godlike Partners — команды менеджеров, версия 1.1.1

Добавлены команды тимлидов, наследование ссылок выплат, закрытая финансовая аналитика владельца и Telegram-постбеки для отдельных партнёров. Внешний вид и существующие кабинеты сохранены.

## Быстрый запуск

Требуется Node.js 22.13+ или Node.js 24 и постоянное место для SQLite и файлов `uploads`.

```sh
npm ci
cp .env.example .env
# Заполните .env своими значениями, затем:
npm start
```

В production используйте HTTPS. Админка: `/admin`. Инструкция: `/admin/team-guide.html`. На Windows `.env.example` можно скопировать вручную. В архиве только примеры настроек, реальных ключей нет.

## Обновление работающего проекта

1. Остановите старую версию и сохраните резервную копию каталога данных целиком: `godlike.db`, возможных `godlike.db-wal` и `godlike.db-shm`, каталога `uploads`. Копирование работающей базы без SQLite backup API может дать несогласованную копию.
2. Замените файлы приложения файлами из архива. Сохраните существующий `.env`, `JWT_SECRET` и путь к данным. Не удаляйте и не подменяйте базу пустой или тестовой базой.
3. На Railway сохраните прежний Volume и `RAILWAY_VOLUME_MOUNT_PATH`. На другом хостинге сохраните прежний `DATA_DIR`. Без этих параметров база находится в `data/` рядом с `server.js`.
4. Выполните `npm ci` и запустите приложение. Миграции автоматически добавят столбцы и таблицы, сохранив существующих пользователей, ссылки, профиты и расходы.
5. Войдите главным админом → «Моя команда» → «Назначить тимлида», чтобы распределить существующих менеджеров. Новые менеджеры, созданные тимлидом, сразу относятся к его команде.
6. Укажите `PUBLIC_URL` с настоящим HTTPS-доменом и `REPORT_TIMEZONE` (по умолчанию `Europe/Moscow`).
7. Проверьте вход главным админом и менеджером, наследуемые ссылки, отчёт и тест Telegram со своими реквизитами.

Старые индивидуальные ссылки менеджеров сохраняются. Для возврата наследования главный админ очищает список ссылок менеджера и сохраняет. Если в старой базе есть администраторы, но никто не помечен главным, главным становится первый найденный администратор. Новых главных админов через интерфейс создать нельзя.

## Права

| Возможность | Главный админ | Менеджер / тимлид |
|---|---|---|
| Видеть менеджеров | Все | Себя и подчинённых всех уровней |
| Добавить менеджера | В выбранную команду или напрямую | Только в свою команду |
| Блокировать / сменить пароль | Любому менеджеру | Только подчинённым |
| Назначить руководителя | Да | Нет |
| Привязать свободного партнёра по email | Да | Себе или своей команде |
| Перевести партнёра | Между любыми командами | Внутри своей ветки |
| Работать с партнёрами | Все | Свои и своей команды |
| Изменить список ссылок выплат | Да | Нет |
| Выбрать партнёру разрешённую ссылку | Да | В своей команде |
| Настроить Telegram-постбеки | Любому партнёру | Партнёрам своей команды |
| Профиты и дневной отчёт | Все сотрудники | Своя команда, включая себя |
| Расходы и чистая прибыль компании | Да | Нет, включая прямые запросы к API |

Каждый менеджер автоматически может быть тимлидом. Подчинённый также может создать свою команду. Управление доступно только вниз по иерархии. Перенос команды не допускает циклов. Блокировка тимлида не блокирует автоматически сотрудников: каждого блокируют отдельно. Блокировка и смена пароля отзывают сеансы; разблокировка не восстанавливает старые сеансы.

## Если партнёр зарегистрировался без привязки

В «Партнёрах» нажмите «Привязать по email», введите точный email регистрации, проверьте найденные имя/email и выберите себя либо менеджера команды. Поиск показывает только незакреплённого партнёра и не раскрывает его баланс до назначения. Учётная запись должна уже существовать.

Для перевода внутри команды откройте карточку партнёра и смените «Ответственного менеджера». Назначить можно только активного сотрудника в своей ветке. Перевод между разными командами и снятие назначения доступны главному админу. В его карточке партнёра есть история ручных назначений: дата, инициатор, прежний и новый менеджер. Повторное назначение того же ответственного не создаёт лишнюю историю. Одновременно забрать одного свободного партнёра в две команды нельзя.

Баланс, сообщения, транзакции и настройки партнёра сохраняются. Наследуемые ссылки выплат/бот определяются по новому менеджеру; индивидуальные настройки партнёра сохраняются. Старые ручные записи профита остаются у автора и автоматически не переносятся.

Реферальная ссылка дополнительно сохраняется в подписанном cookie на 30 дней в том же браузере. Это запасной способ для регистрации без доступного localStorage или без `ref` в адресе. Другой браузер/устройство не получает эту привязку автоматически. Переход существующего партнёра по ссылке другого менеджера не меняет ответственного. При ручном переносе следует пользоваться карточкой или привязкой по email.

## Выплаты

Список разрешённых ссылок определяется при каждом запросе: индивидуальные ссылки менеджера → ближайший руководитель с индивидуальной настройкой → главный админ → общие настройки сайта.

Первая ссылка основная, остальные доступны для выбора в карточке партнёра. Если выбранную ссылку убрали из списка, партнёр получает действующую основную. Разрешены до 20 HTTPS-ссылок без логина/пароля в URL. Изменять и добавлять списки может только главный админ.

## Отчёт и деньги

«Отчёт команды» показывает профит за выбранный день, его неделю (пн–вс), месяц и всё время. По сотрудникам: регистрации партнёров, количество партнёров с начислением баланса, ручные показатели Telegram/групп, статус сдачи отчёта, автоматические действия в кабинете и профиты. Доступны последние 30 действий каждого сотрудника за день. Состав команды и принадлежность партнёров берутся по текущим назначениям; историческая оргструктура отдельно не фиксируется.

Сообщения в Telegram и группы вносит менеджер через «Мой отчёт» — это не автоматический подсчёт его переписки. Автоматически журналируются успешные изменения через административный API. Старые действия до обновления в журнал не восстанавливаются.

В «Финансах» главного админа добавлена таблица «Доход и чистая прибыль по менеджерам». Результаты личные: доход подчинённого не включается повторно в строку тимлида. В расходах можно выбрать менеджера или общий расход компании.

Существующая формула сохранена: вознаграждение менеджера — 50% записи профита; при сумме записи строго больше $50 шлюз — 20%, иначе 0%. Чистый результат компании от менеджера = сумма профитов − вознаграждение − шлюз − расходы по записям − отдельные расходы на менеджера. Общие нераспределённые расходы вычитаются из результата компании один раз. Вознаграждение из профита не вносите повторно как расход. Дополнительная комиссия тимлида не вводилась.

Финансовая модель ведётся в USD. Сумма входящего постбека — отдельная сумма события; она не зачисляется в баланс и финансовый отчёт автоматически. В финансовой таблице остаются ручные данные менеджеров и главного админа.

## Telegram

Полная инструкция: [TEAMLEAD-GUIDE.md](TEAMLEAD-GUIDE.md), также доступна в интерфейсе в HTML. Есть индивидуальные чаты партнёров, отдельный или наследуемый бот, четыре типа событий, тест, смена ключа, журнал и повторная отправка ошибок.

Настоящие конверсии нужно подключить в трекере/партнёрской сети. Старый `/go/:offerId` в исходном проекте по-прежнему является заготовкой: пишет клик и не перенаправляет на реальный продукт. Этот релиз не подменяет реальные регистрации и депозиты демонстрационными цифрами.

## Проверки

```sh
npm test
```

Тесты создают временную базу и проверяют команды, запреты доступа, ссылки, приватность финансов, расчёты, дневной отчёт, постбеки и отзыв сеансов. Отдельный тест проверяет миграцию старой базы. Telegram в тестах заменён локальным ответом; внешние сообщения не отправляются. Реальная проверка доставки требует вашего бота, чата и публичного сервера.

Новые компоненты: `src/utils/team.js`, `src/routes/team-admins.js`, `src/routes/telegram-settings.js`, `src/routes/postback.js`, `src/utils/telegram-postbacks.js`, `public/admin/team.js`, `public/admin/team.css`. Изменены миграции, авторизация, административные и партнёрские маршруты.
